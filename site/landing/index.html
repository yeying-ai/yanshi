Yanshi 生成的 .pptx 幻灯片是整页 AI 图片贴片，还是 PowerPoint / Keynote 原生可编辑组件？ Are generated .pptx decks flat AI images or native editable PowerPoint shapes?

是原生可编辑的 OOXML 演示文稿。Yanshi 内置纯 Rust 编写的 OOXML 写入器，直接输出标准 PowerPoint 形状（<p:sp>）、原生表格（<a:tbl>）、代码卡片与连线，在 PowerPoint、Keynote 或 WPS 中打开即可逐字编辑；同时按每页意图分流融合 D2/Typst/TikZ 矢量架构图与 6 种艺术风格概念插画，并同步导出 16:9 .pdf 与交互式 .html。 They are real, native OOXML presentations. Yanshi’s pure-Rust OOXML writer emits standard PowerPoint shapes (<p:sp>), native tables (<a:tbl>), code callouts, and connectors that open directly for text and layout editing in PowerPoint or Keynote — combined per-slide with verified D2/Typst/TikZ diagrams and 6 art-directed illustration styles, plus matching 16:9 .pdf and .html exports.

没有图像生成或语音 TTS API Key 可以运行么？支持哪些大模型服务商？ Can I run workflows without image or TTS API keys, and which LLM providers are supported?

完全可以。只需配置任一文本大模型 Key（例如单个 DEEPSEEK_API_KEY 即可同时解锁 deepseek-flash 视觉理解以及原生 TTS、ASR、联网搜索、网页抓取与扫描件/图片 OCR）即可开箱运行 slides.yml、report.yml、repo_architecture.yml、backend_project_planner.yml、paper_reader.yml、mindmap.yml 等绝大多数生成器。运行时原生支持 OpenAI、Anthropic Claude、Google Gemini、Moonshot（Kimi）、StepFun、智谱 GLM、阿里百炼 DashScope、DeepSeek、MiniMax 以及本地 Ollama。 Yes. A single LLM key — for example DEEPSEEK_API_KEY, which unlocks deepseek-flash vision plus native TTS, ASR, web search, Markdown fetch, and PDF/image OCR — runs Studio generators out of the box, including slides.yml, report.yml, repo_architecture.yml, backend_project_planner.yml, paper_reader.yml, and mindmap.yml. Yanshi natively supports OpenAI, Anthropic Claude, Google Gemini, Moonshot, StepFun, GLM, DashScope, DeepSeek, MiniMax, and local Ollama.

Yanshi 与 LangGraph、Dify 或单一 AI PPT 工具有何核心区别？ How does Yanshi differ from LangGraph, Dify, or single-purpose AI slide tools?

Yanshi 将「默认并发 DAG 工作流」、「原生跨核并行 ReAct / 多智能体循环（WorkflowTool / AgentNode / AgentTool 会话隔离并行）」与「运行期动态编译工作流」统一在同一套零运行时依赖耦合的 Rust L0 窄腰内核上：既编译为单一高性能静态二进制（调度与预算护栏开销低于 1ms，内置 76 模型硬性 cost_limit_usd 祖先预算池熔断与零数据库 workflow run-batch 本地批处理），又以一等公民磁盘文件句柄（FlowValue::File）打通 PPTX、1080p 配音视频、PDF、Excel 与播客渲染，免除 Python 环境冲突与 Base64 内存膨胀。 Yanshi unifies deterministic concurrent DAGs, multi-core parallel autonomous agent loops (ReAct, Plan-Execute, Handoff/Blackboard/Debate, isolated AgentNode/AgentTool & parallel WorkflowTools), and runtime-compiled dynamic workflows on one narrow-waist Rust kernel. You get a single fast binary (< 1ms scheduling overhead, built-in 76-model cost_limit_usd ancestor budget pool, and zero-DB yanshi workflow run-batch matrix execution) with first-class FlowValue::File multimodal renderers (.pptx, 1080p .mp4, .pdf, .xlsx, .mp3) and zero Python dependency drift or Base64 memory bloat.

在抓取外部网页、分析陌生代码仓库或运行绘图代码时如何保障宿主机安全？ How does Yanshi isolate untrusted repos, web fetches, and LLM-generated code?

SecurityProfile::Production 采用默认闭锁（fail-closed）策略：宿主机工具自动运行于 macOS sandbox-exec 或 Linux Landlock + seccomp + cgroup v2 操作系统沙箱中；code_exec 绘图代码强制运行在无网络隔离容器（ContainerBackend）内；repo_snapshot 仅静态解析清单与导入树而不执行仓库代码；HttpTool 逐请求绑定 DNS 解析并归一化 IPv6 地址以阻断 DNS 重绑定 SSRF；技能包与插件默认强制校验 Ed25519 数字签名。 Under SecurityProfile::Production, security is fail-closed by default: shell and renderer subprocesses run inside OS sandboxes (macOS sandbox-exec or Linux Landlock + seccomp + cgroup v2), code_exec requires a zero-network ContainerBackend, repo_snapshot inspects manifests statically without executing code, HttpTool pins DNS per request to block TOCTOU SSRF, and marketplace skills/plugins verify Ed25519 signatures.

多阶段长视频或深度报告生成中途失败，恢复执行会重复消耗大模型费用么？ If a long multi-stage video or report run is interrupted, do resumed runs re-bill completed steps?

不会。开启 --checkpoint（或通过网关与桌面端运行）后，每个节点完成即刻落盘检查点及已累计账单金额与产物 SHA-256 清单。执行 yanshi workflow resume <run_id> 时仅从尚未完成的下游节点继续并发调度，已成功的大模型与生图/配音节点直接复用落盘结果，不重复计费。 No. With --checkpoint (and automatically on the gateway/Studio), Yanshi persists node outputs, SHA-256 file manifests, and accrued spend after every node. Running yanshi workflow resume <run_id> replays completed upstream outputs from disk and executes only unfinished downstream nodes under the remaining cost budget.
